# 代码评审规范

适用于 `apps/extension` 的 TypeScript、Vue 面板、游戏功能模块和微端壳。门户与服务端按同一套级别执行，界面细节以各自产品为准。

评审通过的标准只有一条：这次改动让代码库更健康，并且下面的强制项全部满足。推荐项做不到时，要在改动说明里写清原因和用户会看到什么。

级别与国内大厂规约一致。

| 级别 | 含义 |
| --- | --- |
| 强制 | 不满足不能合入 |
| 推荐 | 默认要做。例外必须写明 |
| 参考 | 视场景采用，不作为否决理由 |

评审看设计、行为、边界、测试和是否破坏已有约定。缩进、引号、导入排序交给格式化工具，不在评审里来回改。

---

## 1. 评审怎么进行

一次改动只解决一件事。混进无关格式化、顺手重构或另一块功能，先拆开。

作者在请求评审前完成文末自检，并写清三件事：用户会看到什么变化、微端和只装油猴的浏览器是否同一行为、怎么验证。

评审意见按这个顺序写。

1. 位置：文件和行，或组件名加交互。
2. 后果：用户会看到什么，或哪条强制项被打破。
3. 改法：具体改成什么样。只说「再优化一下」不算意见。

风格偏好不是强制项时，标明「建议」，不挡住合入。强制项写「必须改」。

看到写得好的地方点一句。评审不是只挑错。

## 2. 设计与正确性

**强制**

- 先能正确完成用户那件事，再谈抽象。为了复用拆出没有第二个调用方的层次，不算设计。
- 写清状态边界：没有数据、加载中、失败、开关关闭、字段缺失、值为 `0` 或 `1` 而不是布尔。
- 同一份数据只有一个写入方。展示方只读。清掉之后，要检查还有没有别的路径用旧数据写回来。
- 失败要有用户能看懂的结果。空的 `catch` 只允许出现在清理阶段，并且注释写明忽略的是哪一种失败。
- 不留下没有调用方的半成品。接不上的模块不要先合进来。

**推荐**

- 函数名是动作，读名字能知道做完以后什么变了。
- 一个函数只做一件事。又拉数据又改界面又写存储的，拆开。
- 注释只写当前行为。不写对照过哪份旧脚本，不写只给旧代码用的混淆符号。

## 3. 命名与常量

业务里看不出含义的数字、单字母和缩写，统一放进 `src/const/`。业务文件只引用名字。

**强制**

- 一个常量文件只放一类。导出名能看出这个值是什么。
- 同一个数字只在常量里出现一次。业务文件不得再抄一遍。
- 禁止用 `a`、`b`、`x`、`n`、`w`、`h` 当变量名。宽高写 `width`、`height`。坐标偏移写 `offsetX`、`offsetY`。
- 可以留在原地的只有：`0`、`1`、`-1`、空字符串、`true`、`false`，以及从接口、配置、图片上读出来的数。
- 枚举式的状态用有名字的常量或联合类型，不用裸的 `0`、`1`、`2` 表示「图片、视频、特效」这类业务含义。
- 存储键、事件名、窗口类名、超时时间，都用常量。禁止在多个文件各写一份相同字符串。

**推荐**

- 常量文件从 `src/const/index.ts` 再导出，调用方从入口引用，避免路径散落。
- 颜色、字号、间距、层级如果会在两处以上使用，进常量或现有样式变量，不在组件里新写一份色值。

**参考**

- 只在某一个绘制函数里使用、且旁边已有同组命名常量的笔画像素，跟那组常量放在一起，不要散落在调用参数里。

## 4. 组件通信

面板是 Vue。游戏能力在 `src/features`。两边不要互相穿透。

**强制**

- 父组件把数据通过 `props` 传给子组件。子组件用 `emit` 通知父组件发生了什么。子组件不修改 `props`。
- 事件名是用户动作或已经发生的事实，例如 `close`、`select`。不用 `onXxx` 当事件名，回调前缀留给父组件自己的处理函数。
- `props` 要声明类型和是否必填。布尔开关默认值写在声明里，不在模板里用空值凑合。
- 组件不直接改另一个组件的数据，不通过父实例、根实例或全局变量互相调用。
- 配置的读写只走 `configStore`。组件可以订阅变更，不可以自己再维护一份会和配置分叉的开关。
- 游戏规则、协议处理和界面展示分开。组件负责展示和发出意图。能不能做、做成什么样，放在功能模块。
- 跨功能需要协作时，走现有的配置、明确的回调或已有事件。不为了省事去读另一个功能的内部变量。

**推荐**

- `provide` / `inject` 只用于整棵界面树都要的依赖，例如平台能力。临时的选中项、弹窗开关不要塞进注入。
- 兄弟组件需要同一份界面状态时，状态提升到共同的父组件。
- 列表渲染必须有稳定且唯一的 `key`。不用数组下标当 `key`，除非列表只追加、不重排、不删除。

**参考**

- 一个设置区块对应一个组件。区块内部的纯计算抽到同目录的 `.ts`，模板里不写长表达式。

## 5. 生命周期与卸载

谁注册，谁释放。组件卸载、功能 `dispose`、热更新拆掉上一轮，三条路径都要走到同一套清理。

绑定时用的函数，卸载时必须用同一个函数引用去摘。匿名函数包一层再摘另一个函数，监听会留下来，下次挂载再叠一层。

**强制**

组件在 `onBeforeUnmount` 里成对释放。功能模块在返回的 `dispose` 里成对释放。至少检查这些：

| 注册了什么 | 卸掉时做什么 |
| --- | --- |
| `window` / `document` 的 `addEventListener` | 同一个函数 `removeEventListener` |
| `setInterval` / `setTimeout` | `clearInterval` / `clearTimeout` |
| `requestAnimationFrame` | `cancelAnimationFrame` |
| `configStore.subscribe` 或同类订阅 | 调用它返回的取消函数 |
| `ResizeObserver`、`MutationObserver` | `disconnect` |
| 游戏舞台、分发器上的 `on` | 同一个接收者和同一个函数 `off` |
| 方法包装 | `restoreAll`，或按对象恢复到包装前 |
| `URL.createObjectURL` | `URL.revokeObjectURL` |
| 视频、音频元素 | 暂停、去掉地址、从文档移除 |
| 自己加到游戏场景上的节点 | 从父节点摘掉。游戏原来的节点留在原地 |

**强制**

- 卸载顺序是：先停定时器和监听，再恢复被包装的方法，最后销毁自己创建的节点。不要先拆节点，导致回调里还去碰已销毁的对象。
- 异步操作回来时，如果组件或控制器已经卸载，不得再改界面、写存储或挂新的监听。用代数或已销毁标记丢掉过期结果。
- 清理过程里的失败可以忽略，但要注释写明忽略的是哪一步。不可以借这个 `catch` 吞掉正常业务错误。

**推荐**

- 订阅放进数组，卸载时统一调用。不要在每个分支里各记一个可能忘记的取消函数。
- 开发时的热更新要走和正式卸载相同的 `dispose`。只在生产路径清理，开发路径会套娃。

## 6. 界面规范

小抄面板的详细约束以 `.cursor/rules/xiaochao-panel-ui.mdc` 为准。评审时下面这些和那份规则一起看。游戏里用 Laya 画出来的功能界面，有单独视觉约定的，只允许那一种样式，不得再做一套 DOM 浮层。

**强制**

- 设置类弹窗只用 `BaseDialog`。定位只改 `BaseDialog` 和 `dialog-layout.ts`。业务组件不写 `position: fixed` 全屏居中，不自己算 `left` 和 `width`。
- 弹窗必须同时落在面板矩形和浏览器视口里。窄面板、贴右停靠、折叠后再展开，四种情况内容都不得横向撑出。过长内容纵向滚动。
- 弹窗主宽度不用 `max-content`，不用 `100vw` 代替面板实际宽度，不用过大的 `min-width`。
- 层级只用 `src/ui/display-layer.ts` 里的 `DOM_OVERLAY_Z`。不在组件里再写一套 `z-index`。
- 样式要能在偏旧的微端里生效。不用 `:is()`、`:has()`、`inset` 这类会让整条规则失效的写法。
- 同一块界面同时具备四种状态里用得到的那些：加载中、没有数据、失败、正常内容。不把空白留给用户猜。
- 文案用简体中文，说用户能做的事和结果。不把内部模块名、协议字段显示到界面上。
- 一个弹窗只有一个主操作。不可恢复的操作要先确认，并写清会失去什么。

**推荐**

- 字号、字色、背景、圆角沿用 `panel-shell-styles` 里已经在用的值。新区块不另起一套视觉。
- 可点击区域要能点中。设置项的开关和文字点哪都能切换。图标按钮要有文字说明，至少有悬停说明。
- 键盘：弹窗打开后 `Escape` 关闭，且不误关游戏自己的弹窗。关闭后焦点回到打开之前的位置。
- 列表和表单在面板大约 200 像素宽时仍然可读。长文案换行，不靠横向滚动。

**参考**

- 间距按 4 的倍数取。已有区块的间距和它对齐，不为了一个新区块单独用 5、7、13 这种数。
- 动效只用于状态变化，时长和面板已有过渡接近。不用动画掩盖加载失败。

改界面后至少看三种布局：面板贴右停靠、面板很窄、折叠后再展开。弹窗四边仍在面板内，右侧不超出屏幕。

## 7. 游戏运行时

包装游戏方法、换背景、拦动画，除了满足第 5 节的卸载，还要保证这一步做完画面还能画出来，游戏不会一直等这次播放，方法也不会再调用自己。

**强制**

- 方法只挂在当前这一个对象上。不写到多个座位或多个特效共用的原型上。沿着原型链找到真正拥有该方法的那一层再替换，会让后续调用再次进入包装函数。
- 进局还在等的动画必须让原来的播放做完。直接返回空结果，游戏会一直等。
- 底图的加载函数被包住之后，仍要调用原来的加载。进桌时不清掉底图地址，不把底图藏起来。
- 自己的图还没有画出来时，留下游戏原来的底图和舞台背景色。
- 背景层的绘制入口不包成「绘制时再调用自己」。

**推荐**

- 新增或改动这类包装时，补测试：写到共用原型会被拒绝，或从原型再调用不会无限递归。图没好时，原来的底图还在。

## 8. 微端与浏览器

交付物是两条入口共用同一套业务代码。只在微端里能跑，不算做完。

**强制**

- 必须兼容微端和浏览器脚本。两条入口共用同一套业务代码，用户能完成的事和看到的结果一致。只在微端里测过，不能合入。
- 功能写在 `src/features` 和 `src/core`。平台差异只通过平台适配和已有的设置读写进入。业务里不读 `window.electron`，不调用只在油猴里存在的接口，不引用 Node 模块。
- 油猴是单文件整包。共用代码不得依赖必须拆成多份才能加载的构建结果。
- 外链、配置、本地持久化走统一的平台方法。不把只有主进程才有的状态当成功能是否正确的条件。
- 与运行环境无关的行为，禁止只给微端加一条分支。浏览器做不到时，注释写清用户会看到什么，并给出可用的降级。

**推荐**

- 和平台有关的适配有单测，或在改动说明里写明微端和浏览器各看哪一步。

## 9. 性能

**强制**

- 不在每一帧里做全量查找、全量布局或整张大图的拷贝。尺寸没变就不要重算布局。
- 同一件事只用一套循环。游戏逐帧回调和 `requestAnimationFrame` 不要同时推动同一次绘制。
- 定时全量扫描窗口或场景树，必须有退出条件，并且卸载时清掉。能在事件发生时处理的，不用固定间隔去扫。
- 不在高频路径上构造调用栈再做字符串匹配。

**推荐**

- 大列表需要频繁更新时再考虑虚拟滚动。设置页这种短列表不必上。
- 图片和视频按显示尺寸解码。上传前能拒绝的无法解码文件，不要等到铺到画面上才失败。
- 监听和订阅的数量在反复开关、反复进出场景后保持不变。评审时看卸载是否真的摘掉，而不只看有没有写 `dispose`。

**参考**

- 广度搜索节点很多时，不用数组头部弹出。深度有上限的小树可以保持简单。

## 10. 安全与数据

**强制**

- 不把密钥、口令、用户隐私写进仓库、日志和界面文案。
- 不把不可信字符串拼进 HTML。需要展示文本就用文本节点或框架的文本插值。
- 持久化按账号分开的数据，切换账号后读到的必须是当前账号的那一份。写之前确认账号已经取到，避免写进默认桶再被下一个账号读到。
- 上报和请求拦截只针对明确的地址或明确的本地写入。不用调用栈判断是不是自己触发的。

**推荐**

- 日志写失败原因和用户可复现的动作。不把整份配置、牌局数据或文件内容打出来。

---

## 11. 测试

**强制**

- 改了判断条件、状态翻转或卸载逻辑，要有对应测试。测试证明坏的情况进不来，而不只证明好的例子能过。
- 游戏方法包装和换背景的测试，按第 7 节的强制项覆盖。
- 界面逻辑能抽成纯函数的，用纯函数测试。不把「打开过页面」当成验证。

**推荐**

- 名字识别、窗口类名、协议字段这类规则，同时写会命中的例子和长得很像但必须放过的例子。
- 异步等待要测超时和卸载之后结果才回来这两种情况。

## 12. 评审意见示例

必须改的写法：

> `SkinPanel.vue` 在挂载时监听了 `resize`，卸载时没有摘掉。反复打开设置会叠多层回调，拖动窗口时面板会跳。请把回调存成具名函数，在 `onBeforeUnmount` 里用同一个函数移除。

建议的写法：

> 建议把格子间距放进 `src/const/`，和预览宽高放在一起。现在功能是对的，这不是合入条件。

不通过的写法：

> 这里有点乱，优化一下。

---

## 13. 提交前自检

作者在请求评审前逐项确认。

1. 这次只做一件事，说明里写了用户会看到什么。
2. 强制项里和这次改动有关的都满足。做不到的推荐项写了原因。
3. 新的数字和业务状态进了 `src/const/`，业务代码里没有单字母变量。
4. 组件只通过 `props` 和 `emit` 通信，没有去改别的组件。
5. 每一个监听、定时器、订阅、对象地址、游戏节点，都在卸载时用同一个引用释放。
6. 弹窗用 `BaseDialog`，窄面板和贴右停靠时不会撑出屏幕。
7. 包装游戏方法之后，画面还能画，游戏不会一直等，方法不会调用自己。
8. 兼容微端和浏览器脚本。只装油猴、不装微端时，这条功能仍然完整，看到的结果和微端一致。
9. 关键翻转有测试。界面改动至少看过贴右、窄宽、折叠后再展开。
10. 没有把构建产物、本地缓存和调试摘录放进提交。
