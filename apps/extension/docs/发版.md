# 发版

小抄版本是注入到微端里的脚本版本。它写在工程根目录 `package.json` 的 `version`，打包后出现在 `xiaochao.js` 头部的 `@version` 和线上清单里。微端自己的版本与此无关，发版时不改、也不看它。

线上清单是 `https://xc.95chong.cn/downloads/manifest.json`。下载页是 `https://xc.95chong.cn/downloads`。客户端按清单里的小抄版本逐段比较，远程更大才提示更新。新版本必须大于当前线上版本，否则已注入旧脚本的客户端不会弹更新，只能手动安装 `wd-xc.zip`。

## 步骤

1. 修改 `d:\workspace\sgs-extension\package.json` 的 `version`。

2. 在 `d:\workspace\sgs-extension` 执行：

```bash
npm run pack
npm run copy:portal
```

`npm run pack` 先用 Vite 构建 `dist/electron/xiaochao.js`，再生成：

| 本地文件 | 含义 |
| --- | --- |
| `release/wd-xc.zip` | 手动安装包 |
| `release/app.zip` | 自动更新包 |
| `release/xiaochao-manifest.json` | 清单，`version` 等于上面的小抄版本，并带 `app.zip` 的 sha256 |

`npm run copy:portal` 把这三个文件拷到 `d:\workspace\portal\public\downloads`。清单在网站上的文件名是 `manifest.json`。

1. 在 `d:\workspace\portal` 执行：

```bash
npm run deploy
```

这一步会 `next build`，再通过 SSH 把站点同步到 `admin@123.56.3.130:/opt/xc/dist`。终端出现「已同步到 admin@123.56.3.130:/opt/xc/dist」后，下载页和清单才是新版本。

1. 到小抄服务端项目，更新返回的版本号信息

```bash
npm run deploy
```

## 线上地址

| 地址 | 内容 |
| --- | --- |
| `https://xc.95chong.cn/downloads` | 下载页 |
| `https://xc.95chong.cn/downloads/manifest.json` | 清单 |
| `https://xc.95chong.cn/downloads/app.zip` | 自动更新包 |
| `https://xc.95chong.cn/downloads/wd-xc.zip` | 手动安装包 |

## 总结发版命令

```sh
# 小抄项目构建
npm run pack:portal
# 上传到门户服务器上应用的downloads目录， 如果门户代码有更新执行 deploy
npm run deploy:downloads 
# 更新小抄服务端的接口的返回数据
npm run deploy
```

## 更新是否无感

**基本无感。** 微端和浏览器都在后台把新版准备好，等玩家不在打牌时把游戏页刷新一次，刷新后提示「小抄已更新到 x」。

什么时候刷新：

1. 游戏页在首页或大厅，不在牌桌、房间里，不在匹配或找房，也没和别人组队。
2. 窗口在后台，或者在前台但 5 分钟没动鼠标键盘。
3. 每 5 秒看一次，连着两次都满足才刷。

同一个标签页同一个版本只刷一次，刷完没换上就改成亮「去更新」，让玩家手动装。新版下好后点版本按钮可以立刻换，不在首页或大厅时点了不刷。

游戏嵌在 4399、7k7k 这类平台网页里时不替玩家刷新：只能刷新游戏那一块，平台给的登录参数可能已经过期。这时只把新版下好，玩家下次打开或自己刷新整个网页时换上，不亮「去更新」。

在后台准备了 10 分钟还没好，例如一直下载失败，就改成亮「去更新」。

### 微端

正式微端走 `tools/release-app-shell/micro-client-update.js`：

| 步骤 | 会不会打扰用户 |
| --- | --- |
| GET `https://95chong.cn/api/xiaochao-version` | 后台，无感 |
| 下载 `scriptUrl`，核对 sha256 和 `@version`，写进 userData 的 `xiaochao.js` | 后台，无感，不刷新游戏页 |
| 游戏页里的小抄通过 `xiaochao-update-status` 问到新脚本已就绪 | 等空档自己刷新 |
| 清单 `shellVersion` 大于本地 `package.json` 的 `xiaochaoShellVersion` | 启动后 3 分钟内弹「是否立即更新？」，确认后下载 `app.zip`，再弹 **Windows UAC** |
| 玩家没装整包 | 脚本照样在后台换好 |

外壳版本由 `npm run pack` 计算：`tools/release-app-shell` 里除脚本和说明文档以外的文件有变化，正式发版时 `tools/release-shell-version.json` 里的版本号加 1。**这个文件要提交。**

旧版微端的安装包里没有 `xiaochaoShellVersion`，还是换完脚本立刻刷新，装一次新的整包后才变成等空档刷新。开发壳不登记 `xiaochao-update-status`，有新版只亮「去更新」。

`updates.txt`（`log.xiaochao.org`）只是官网更新日志，供对照逆向，**不参与**本仓库微端更新。

另有一条本地静默路径：启动时 `syncBundledScriptIfNewer` 把安装包内 `xiaochao.js` 同步到 userData（哈希不同就覆盖），**不上网、不弹窗**；这不是线上热更。

游戏壳自带的 `electron-updater`（`AutoUpdaterURL` → 官方 OL 更新源）下载完直接 `quitAndInstall`，与小抄清单无关。

勿给 `appUrl`/`scriptUrl` 乱加会变的 query 当「永久地址」写进客户端常量；下载时可临时加 `t=` 防缓存（当前已如此）。

### 浏览器油猴

正式构建的 `sgs-xc.user.js` 开头是一段启动代码，后面是脚本自带的小抄。构建同时输出 `xiaochao-userscript.js`，只有小抄本体，第一行写版本号。

1. 小抄发现线上有新版，从 `https://95chong.cn/api/xiaochao-userscript` 下载新版代码，核对清单里的 `userscriptPayloadSha256` 和第一行版本号，存进游戏网站的本地数据库。
2. 等空档刷新后，启动代码看到本地有比自带更新的版本就运行它；读不出、对不上或者跑不起来都运行自带的，任何时候只跑一份。
3. 网站安全策略不让运行下载的代码时不下载，退回原来的做法：Tampermonkey 每天按 `@updateURL` 更新，版本按钮亮「去更新」。

Tampermonkey 管理面板里的版本可能比实际运行的旧，以小抄版本按钮上显示的为准。开发构建不带启动代码，有新版只亮「去更新」。

`npm run pack` 把 `xiaochao-userscript.js` 拷到 `release/` 和 `apps/server/data/`，版本服务部署时一起上传。
